# ApeRadar Next design system

The UI/UX skill's compact dashboard and Swiss typography guidance fits the app. Its two generated hero/enterprise marketing layouts did not match a desktop battle tool, so those unverified layouts were discarded. React stack searches returned no verified results; React implementation follows normal typed state and effect ownership practices. No unverified generated master was persisted.

## Tokens

`apps/web/assets/design-tokens.css` defines the base tokens. `apps/web/assets/palette-tokens.css` adds six paired light/dark palettes: graphite, cyan, orange, violet, forest and ocean. Each palette owns its accent, hover, subtle accent surface and foreground colors. Buttons, navigation, focus rings, switches, self-row highlights, appearance controls and the in-app mark inherit these semantic tokens. Primitive HSL channels, four-pixel spacing, numeric typography, radii and motion feed semantic aliases, then button/card/input/table tokens. Tailwind v4's `@theme inline` maps semantic values to utilities. Components do not embed raw hex values. Ship icon tiles share a neutral surface and border across all five classes. Team, rating and success/error colors retain their meaning independently of theme accents; light-mode body text uses slate 800 to soften its weight.

## Layout

A shadcn inset Sidebar frames the workspace with a persistent brand, grouped navigation, and a footer for connection status, settings, and updates. It slides horizontally off canvas at a constant width, fully releases its layout space, and keeps the vertical positions of its contents unchanged. Its open state is remembered locally, and hidden controls are inert; narrow viewports use its Sheet navigation. The sidebar toggle stays at the left of the sticky breadcrumb bar beside a vertical separator, in both expanded and collapsed states. The bar also provides native desktop window controls and the drag region. Closing Sheet navigation restores focus to the toggle, including when it is composed with a tooltip. The overview begins with a single roster toolbar: the win-rate mode and demo badge sit on the left; the refresh action sits on the right and wraps below when needed. Its accessible page heading is visually hidden, and the duplicate title and subtitle block is removed. History, Watchlist, and Help also use visually hidden page headings; Settings retains its visible section title and description. The Watchlist total lives beside its search and type filter, together with the matched count. The chart header contains only its title, and the Help FAQ omits the repeated version footer. Rosters load automatically from the configured game directory; empty states and help actions link to Game connection settings. File-picker, drag-and-drop, upload, and renderer import bridge paths are removed. Workspace card gaps, toolbar spacing, action-row margins, and top/side padding share a 24px spacing value on viewports at least 768px wide and 16px below that breakpoint. Bottom padding remains 12px. Teams share a row only when both cards have at least 30rem; otherwise they stack. Each header contains the average for the selected win-rate mode. Keep ship average damage before total battles and hide total battles first below 470px per card. Tables retain a 20rem minimum width and scroll inside their own container when large text needs more room. Hidden-status badges sit beside the ship name on the second line, so hidden-player rows keep the same compact two-line height as normal rows. Captain names retain the full first line. Hidden-player identities extend across the empty statistics area up to the watch action, including when responsive columns disappear. The roster offers text summaries. Battle history supports search and snapshot playback without record export. The workspace footer uses content-based height, a compact demo action, and 12px of bottom padding. Focusable tooltips reveal full names while preserving privacy settings. Settings use six focused sections and a persistent return action. Player name buttons use the local plain Button variant so their background remains transparent on hover. The row owns its hover and self-highlight background, keeping the self badge and name surface consistent; keyboard focus rings and detail activation remain available. Player details use a Dialog with context, labelled tabs, and focus restoration.

## Appearance and settings

The theme cards and paired palette controls follow the interaction model in [brokenarrow-log-maggot](https://github.com/JamesFlare1212/brokenarrow-log-maggot), especially `AppearanceSettings.tsx`, `useAppearance.ts`, `useSettingsAutosave.ts` and the settings/tokens styles. Theme mode is independent of the selected light and dark palettes. A pair card chooses both palettes; each orb changes only its own mode. System mode follows live OS changes. Settings apply immediately and save automatically with validation and sequential writes; errors retain the draft for retry. Old settings acquire palette defaults without discarding existing preferences. Cached appearance is applied before React renders to reduce theme flashes.

Settings and data surfaces use quiet borders and restrained elevation. The API panel reports actual per-source/region probes, elapsed time, failure reason and the current source; software updates expose check/download/install state, including an explicit reason when a build cannot update.

Interface icons use Lucide React, matching components.json, through the shared Icon component with currentColor and a consistent stroke. Buttons, menus and other shadcn components own icon dimensions; prefix and suffix icons expose data-icon. Loading indicators use the shadcn Spinner. Watch stars use the same Lucide glyph with a filled selected state. The five known ship classes retain their specialized SVG redrawings through ShipGlyph. Keep their silhouettes and use white vectors in dark mode, inverted in light mode. SVG filenames, official Wiki PNG references, URLs and reference SHA-256 digests are recorded in apps/web/src/assets/ship-types/sources.json. The application mark uses Lucide SatelliteDish, with matching generated favicon and native Windows icons. Icons and CSS are bundled locally. All icon buttons have accessible names, and decorative icons are aria-hidden. Status has text. Roster headers are static; each team sorts a display copy by ship class, tier, internal nation order, numeric ship ID, and captain name. Statistics updates and winrate metric changes do not affect this order. Numbers use tabular digits, rates use two decimals. Empty means em dash; an actual zero remains zero. Charts have labelled series, units and a text alternative. The winrate chart uses two smooth ascending lines with one circular marker per public player and a percentage Y axis. Each team spans its own relative rank range; graph sorting never changes roster order. The default 30–70% scale expands for actual outliers. Hover and keyboard focus reveal the selected player and value, respecting name privacy.

## Motion and accessibility

Loading, querying and saving indicators use the local shadcn Spinner, based on Lucide. The application-wide reduced-motion override remains active.

140ms state feedback, 200ms overlay transitions; `prefers-reduced-motion` disables nonessential motion. Buttons/inputs retain visible focus and 36px default desktop controls; compact controls retain at least 24 CSS pixels per pointer target. Forms retain errors. Settings errors link to their controls across sections; only an explicit locate or failed retry moves focus. Minimum text contrast targets 4.5:1 in both themes. Mobile checks at 375px and landscape complement the desktop layout.


## Watch records and search

Player details use ToggleGroup for the three mutually exclusive watch types. Type changes save the current note, and existing records also provide an independent Save note action. Pending writes disable edits; failures retain drafts. Closing an unsaved note requires confirmation. Removing any watch record, from a player dialog, roster menu or watchlist, confirms that its local note is also deleted. Search views announce matched and total counts; empty filtered results provide a clear action that restores focus to the search input.
