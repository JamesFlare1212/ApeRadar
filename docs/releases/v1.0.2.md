## Changes

- Automatically discover current World of Warships installations from Wargaming Game Center
  records and modern Steam libraries, with validated, deduplicated client choices in Settings.
- Validate the 64-bit game executables and installed build before enabling monitoring. Show
  directory validation, detected region, evidence timestamps, and waiting-for-battle states.
- Use automatic region selection by default for new settings. Read the selected server from
  game preferences and recent startup logs without assuming that the installation label `WW`
  identifies a statistics server. Report missing, unsupported, or conflicting evidence instead
  of guessing a region; preserve manual selections.
- Fix queries retaining the previous region after switching to AUTO, restore the primary
  region when mixed-region mode is disabled, and cancel obsolete queries and monitoring scans.
- Follow the operating system theme by default for new settings.

## Validation

- `node scripts/verify-release-version.mjs v1.0.2` passed for all five workspace packages
  and the release tag.
- `pnpm check` passed: type checking, 125 regression tests in 14 files, and design-token validation.
- `pnpm dist:win` passed, including the web and desktop production builds and both Windows
  executable formats. Vite reported a non-fatal JavaScript chunk-size warning.
- `pnpm smoke:desktop` and `pnpm verify:package` passed using isolated application data and
  the generated v1.0.2 portable executable. Desktop checks covered client inspection, region
  display, invalid-directory rejection, discovery IPC, and waiting for an arena file.
- `pnpm verify:updates` passed: update metadata, installer SHA-512 and size, installer blockmap,
  and portable companion file.
- Read-only local-client checks discovered an installed WGC client and parsed current Steam
  library records. A real 24-player replay used the detected NA region after switching to AUTO;
  that routing check used an in-memory database and a mocked statistics provider.
- Live API checks were skipped because `WG_APPLICATION_ID` was not set.
- Update validation covered generated metadata and simulated updater behavior. An actual
  v1.0.1-to-v1.0.2 installation was not performed.
