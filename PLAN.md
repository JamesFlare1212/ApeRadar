## Audit protocol and evidence

1. Prepare isolated demo and test data; do not overwrite real user data or initiate real API requests without an appropriate isolated setup. Record app version, platform, window dimensions, display scale, theme, palette, font size and data state for each finding.
2. Exercise every row of the coverage matrix with pointer and keyboard. Include Tab/Shift+Tab, Enter/Space, Escape, focus visibility and return, scrolling, browser history and relevant screen-reader output. Record steps, expected/actual behavior, screenshots or recordings, and source locations. Do not claim a scenario passed until it is exercised.
3. Measure layout movement during startup, lazy loading, refresh, partial responses, failure, retries, update notices, settings validation and window resizing. Capture element rectangles and layout-shift entries where available; CLS alone excludes some user-initiated shifts and does not cover all Electron interactions. Establish a baseline before setting numerical budgets.
4. Measure actual rendered text and control contrast for the tested palette/state combinations. Check reflow, clipping and discoverability at the supported minimum window size, normal size, 200% zoom and available application font extremes. Determine the supported minimum from the desktop configuration before using it as an acceptance boundary.
5. For each verified issue, record impact and priority, propose a focused change using the local shadcn/ui components and semantic tokens, and agree on measurable acceptance criteria. Implement only after the user authorizes code changes. Add targeted regression coverage where it meaningfully protects the behavior.
6. After any later application changes, run `pnpm check` and `pnpm build`; run `pnpm smoke:desktop` for desktop behavior and `pnpm test:api:live` only when `WG_APPLICATION_ID` is available and isolated test data is in use. Record actual results, test counts, failures and skips. Recheck affected surfaces and update this board.
